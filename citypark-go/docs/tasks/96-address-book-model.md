## Spec
Migration Up (retain existing composite primary key and foreign keys):
```sql
ALTER TABLE user_addresses
  ADD COLUMN id bigint GENERATED BY DEFAULT AS IDENTITY,
  ADD COLUMN name text NOT NULL DEFAULT '',
  ADD COLUMN street text,
  ADD COLUMN apartment text NOT NULL DEFAULT '',
  ADD COLUMN entrance text NOT NULL DEFAULT '',
  ADD COLUMN is_default boolean NOT NULL DEFAULT false,
  ADD COLUMN created_at timestamptz NOT NULL DEFAULT now(),
  ADD COLUMN updated_at timestamptz NOT NULL DEFAULT now(),
  ADD CONSTRAINT user_addresses_id_key UNIQUE(id),
  ADD CONSTRAINT user_addresses_name_length CHECK (char_length(name) <= 40),
  ADD CONSTRAINT user_addresses_street_length CHECK (street IS NULL OR char_length(street) BETWEEN 3 AND 120),
  ADD CONSTRAINT user_addresses_apartment_length CHECK (char_length(apartment) <= 20),
  ADD CONSTRAINT user_addresses_entrance_length CHECK (char_length(entrance) <= 20);
CREATE UNIQUE INDEX user_addresses_one_default ON user_addresses(user_id) WHERE is_default;
```
Old associations remain non-default with `street IS NULL`. Do not parse legacy full text. New timestamps record migration time, not invented historical association times. Existing inserts specifying only user/address IDs still work.

Down must first refuse to discard metadata, using a goose StatementBegin/End block:
```sql
DO $$ BEGIN
 IF EXISTS (SELECT 1 FROM user_addresses WHERE street IS NOT NULL OR name <> '' OR apartment <> '' OR entrance <> '' OR is_default)
 THEN RAISE EXCEPTION 'cannot discard saved address metadata'; END IF;
END $$;
DROP INDEX user_addresses_one_default;
ALTER TABLE user_addresses DROP COLUMN id, DROP COLUMN name, DROP COLUMN street,
 DROP COLUMN apartment, DROP COLUMN entrance, DROP COLUMN is_default,
 DROP COLUMN created_at, DROP COLUMN updated_at;
```
Use independent migration fixtures, following existing migration tests; never roll back the shared test schema used by other tests.

Export:
```go
type Fields struct { Name, City, Street, Apartment, Entrance string }
type Entry struct {
 ID int64; AddressID int64 // AddressID is internal: json:"-".
 Name, City, Address, Street, Apartment, Entrance string
 IsDefault, NeedsReview bool
 CreatedAt, UpdatedAt time.Time
}
func CleanFields(in Fields) Fields
func FieldErrors(in Fields) map[string]string
func FormatAddress(in Fields) string
func DuplicateKey(city, fullAddress string) string
func (s *Store) ListEntries(ctx context.Context, userID int64) ([]Entry, error)
func (s *Store) EntryByID(ctx context.Context, userID, entryID int64) (Entry, error)
```
Add explicit camelCase JSON tags, snake_case db tags and appropriate validation tags to Fields. Fields JSON keys are `name`, `city`, `street`, `apartment`, `entrance`. Entry JSON includes `address` (full immutable text), `needsReview` and timestamps; `id` means association ID.

CleanFields trims Unicode White_Space at boundaries; preserve internal display spelling. FieldErrors returns an empty map for valid input. Count Unicode code points. Exact errors: name >40: `Не больше 40 символов`; city empty: `Выберите населённый пункт`; city >80: `Не больше 80 символов`; street <3: `Укажите улицу и дом`; street >120: `Слишком длинный адрес`; apartment/entrance >20: `Не больше 20 символов`.

FormatAddress joins nonempty street, `кв. ` + apartment, `подъезд ` + entrance with `, `, matching checkout. DuplicateKey returns JSON encoding of a two-string tuple: city and full address, each normalized to NFC, Unicode whitespace collapsed to ASCII spaces, trimmed and lowercased with `strings.ToLower`. It excludes name; never removes apartment/entrance, punctuation or abbreviations. No fuzzy matching. Cross-language cases needed later: Cyrillic case, NBSP, composed/decomposed й, different apartment and entrance, punctuation differences.

ListEntries SQL:
```sql
SELECT ua.id, ua.address_id, ua.name, a.city, a.address,
 COALESCE(ua.street, '') AS street, ua.apartment, ua.entrance,
 ua.is_default, ua.street IS NULL AS needs_review, ua.created_at, ua.updated_at
FROM user_addresses ua JOIN addresses a ON a.id=ua.address_id
WHERE ua.user_id=$1 ORDER BY ua.id;
```
EntryByID uses the same full projection/join with `WHERE ua.user_id=$1 AND ua.id=$2` and no ordering. Missing/foreign entries map through `store.NotFound`. Empty lists serialize as `[]`, never `null`. Legacy entries always need review, preserve `address` verbatim and expose empty structured street; do not infer safety from string length.
